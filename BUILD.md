# Building Silent Heritage

How to build, run and test Silent Heritage from its sources. The
[README](README.md) is for players; [RELEASING.md](RELEASING.md) describes
how the release packages are made.

## Desktop

You need CMake 3.25 or later, Ninja, clang and lld, and git (CMake downloads
SDL3 and Catch2 when configuring). On Linux, SDL3 also needs the usual X11 or
Wayland, audio and GL development packages.

    cmake -S . -B build/release -G Ninja -DCMAKE_BUILD_TYPE=Release \
      -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++ -DCMAKE_LINKER_TYPE=LLD
    ninja -C build/release silent_heritage

Windows builds are cross-compiled from Linux with clang and the mingw-w64
runtime: add `-DCMAKE_TOOLCHAIN_FILE=cmake/mingw-clang.cmake`. `-DSH_VERSION=`
sets the version (`MAJOR.MINOR.PATCH[-suffix]`, `0.0.0-dev` by default).
`packaging/build_desktop.sh linux|windows|macos` builds the release packages
(described at its top). Debug builds (the default) enable ASan and UBSan;
under WSLg, set `ASAN_OPTIONS=detect_leaks=0`.

Two variants can be built. The default, `-DSH_VARIANT=classic`, is the
original game ([CLASSIC.md](CLASSIC.md)). `-DSH_VARIANT=extended` builds
`silent_heritage_extended`, which adds the improvements of
[EXTENDED.md](EXTENDED.md) ([`src/core/features.h`](src/core/features.h) for the interface,
`MissionRules` in [`src/sim/context.h`](src/sim/context.h) for the rules). It keeps its own saves,
so the two can be installed side by side.

## Running

    build/release/src/app/silent_heritage [--data <install dir>] [--nointro]

Without `--data`, the game asks once for the folder of your Silent Hunter
install (the one holding `SH.EXE` and `DATA`) and remembers it. Saves go to
the per-user application folder, never into the install.

The other options:

- **`--setup`:** asks for the install's folder again.
- **`--editor`:** starts the scenario editor instead of the front end.
- **`--viewer [--open <category/item#frame>]`:** opens the asset viewer.
- **`--save <dir>`:** writes the saves to another folder.
- **`--sharp`:** scales the picture with square pixels, without smoothing.
- **`--window WxH`:** opens the window at that size, brought within the
  shapes the window may take (4:3, up to 21:9 with the wide screen); the
  wide-screen layouts follow its aspect.
- **`--touch-panel` / `--no-orders-button`:** shows or hides the floating
  ORDERS button of touch screens (shown by default on Android).
- **`--classic`:** runs the extended variant without its improvements.
- **`--keys <k1,k2,...>`, `--screenshot <file.bmp> [--frames N]`:** press
  keys and save a frame without a window, for tests and screenshots
  ([`src/app/command_line.h`](src/app/command_line.h)).

Alt+Enter toggles fullscreen.

## Android

[`android/build_apk.sh`](android/build_apk.sh) builds a debug-signed package for arm64-v8a and
x86_64 (Android 7.0 or later) without Gradle:

    ANDROID_HOME=<sdk> android/build_apk.sh [--variant=classic|extended]

It needs the Android SDK (`platforms/android-36`, `build-tools/36.1.0`) and
NDK 29, a JDK 17 or later, ninja and zip (and rsync for the local Silent
Hunter edition), and python3 with librsvg and cairo plus the Liberation Sans
Narrow font for the launcher icon. The other settings are described at the
top of the script. The package is `build/android/SilentHeritage-debug.apk`;
the debug key is `debug.keystore` at the repository root (created on first
use, not committed; keep it, since an installed package only accepts updates
signed with the same key, and the released packages are signed with another,
see RELEASING.md).

The game logs what the system sends when the app is left and resumed, and
what became of the resume snapshot, in `SAVE/LIFECYCLE.LOG` (64 KB at most,
then moved to `LIFECYCLE.OLD`). On Android:
`adb shell run-as com.conningtower.silentheritage cat files/SAVE/LIFECYCLE.LOG`;
on the desktop, in the `SAVE` folder of the per-user application folder.

## Tests

    ninja -C <build> sh_tests sh_editor_tests
    SH_DATA=<install dir> <build>/tests/sh_tests
    SH_DATA=<install dir> <build>/tests/editor/sh_editor_tests

With `SH_DATA` pointing at an install (the Commander's Edition, with
`SE.EXE`, for the editor tests), the tests run on the original game files.
Without it, they run on a synthetic install generated by code
([`tests/synthetic`](tests/synthetic)), and the tests of the original's content (tagged
`[content]`) are skipped. `make_synthetic_install <dir>` writes that install
to a directory, for running the game without the original files.

The golden traces ([`tests/golden`](tests/golden)) record the classic game's behaviour on
scripted runs: those in `real/` on the original files, those in `synthetic/`
on the synthetic install. A test fails with the checkpoints that changed.
Re-record them only for a deliberate change of the classic behaviour, with
`SH_GOLDEN_RECORD=1` (or part of a trace's name).

The synthetic install takes the shapes of the original's files and
executables from the manifests in [`tests/synthetic/manifest`](tests/synthetic/manifest) (sizes, frame
boxes, the addresses the code reads; no pictures, sounds or text). When code
starts reading other addresses of `SH.EXE` or `SE.EXE`, refresh the
executables' manifests with a trace build:

    cmake -B build/trace -DSH_TRACE_EXE_READS=ON -DSH_SANITIZE=OFF -DCMAKE_BUILD_TYPE=Release ...
    ninja -C build/trace sh_tests sh_editor_tests
    rm -f trace.log
    SH_DATA=<install dir> SH_TRACE_EXE=$PWD/trace.log build/trace/tests/sh_tests
    SH_DATA=<install dir> SH_TRACE_EXE=$PWD/trace.log build/trace/tests/editor/sh_editor_tests
    SH_DATA=<install dir> SH_SYNTHETIC=1 SH_TRACE_EXE=$PWD/trace.log build/trace/tests/sh_tests
    SH_DATA=<install dir> SH_TRACE_EXE=$PWD/trace.log build/trace/tests/sh_tests "[.synthetic_exe_manifest]"

(`SH_SYNTHETIC=1` runs the synthetic install against the original `SH.EXE`,
for the code paths only the synthetic data takes.) The file and table
manifests are refreshed by `[.synthetic_manifest]` with `SH_DATA` set.

## Source layout

`src/` holds one library per module: `core` (basic types, file access, the
original's fixed-point arithmetic), `assets` (the original file formats),
`platform` (SDL3: window, input, audio), `gfx` and `view` (sprites, fonts,
the 3D view), `audio`, `ui` (the original's dialog toolkit), `sim` (the
simulation), `game` (stations, screens, missions, career), `editor` (the
scenario editor) and `app` (the programs). `tests/` holds the Catch2 tests,
`tools/` the build-time tools (the launcher icons), `android/` and
`packaging/` the packaging.

[`docs/`](docs) describes the original game's file formats ([`formats.md`](docs/formats.md)), its data
tables, simulation objects and behaviour ([`structures.md`](docs/structures.md)), the scenario
editor (the `editor-*.md` files), and the dates of the boats' equipment
([`equipment.md`](docs/equipment.md)). Code comments often cite the address and name of the
original function being reimplemented, e.g. `draw_sprite_clipped (0xaaa9c)`:
addresses in the relocated `SH.EXE` (or `SE.EXE` when noted).
